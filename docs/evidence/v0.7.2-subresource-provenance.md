# v0.7.2 Subresource Provenance Evidence

Captured on 2026-07-13 with the final v0.7.2 implementation. This slice tracks
Buffer/Texture2D writes and copies by subresource in the owned D3D11 target. It
does not establish safety for shader/UAV writes, views, aliases, fences, or an
external process.

## Contract

- Ring ABI v4 carries explicit destination/source subresource indices and a
  stable region key derived from offsets and the source box.
- `Map/Unmap` and `UpdateSubresource` advance only the addressed subresource
  generation while also invalidating whole-resource copy provenance.
- `CopyResource` advances every destination subresource generation.
- `CopySubresourceRegion` compares resource IDs, subresource generations,
  destination offsets, and the source box before classifying a repeat.
- Regional copies are diagnostic-only and are always forwarded.
- Empty source boxes remain no-ops in the provenance model.
- Exact event order, byte totals, per-mip generations, lifecycle state,
  readback hashes, and rollback must all agree.

Microsoft documents `CopySubresourceRegion` as an asynchronous GPU copy and
defines an empty source box as a no-op:
[ID3D11DeviceContext::CopySubresourceRegion](https://learn.microsoft.com/pt-br/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-copysubresourceregion).
Subresource indices follow the D3D11 mip/array layout:
[D3D11CalcSubresource](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-d3d11calcsubresource).

The workload copies mip 1 twice, writes only mip 0, and copies mip 1 again. The
third copy remains a candidate because the unrelated mip write does not erase
its provenance. An empty box leaves the generation unchanged. After a mip 1
write, two same-sized partial copies with different destination offsets remain
distinct; only a later unchanged full-region repeat becomes a candidate again.

## AMD Hardware Run

- Adapter: AMD Radeon RX 580 2048SP
- Trial design: 1 excluded warmup pair and 10 measured pairs
- Native/managed runs: 22
- GPU timing valid: 10/10 measured pairs
- Subresource contract valid: 22/22 runs
- Automatic destructions: 1,408 total
- Provenance and Release-hook failures: 0
- Content and rollback valid: 22/22 runs

The positive-performance gate was **allowed only for the declared GPU workload
scope** `owned-d3d11-copy-elision-gpu-workload-only`. GPU paired delta was p50
`-0.64 us` (`-3.213%`) and p95 `-0.072 us`; 9/10 pairs favored the optimized
run and one tied. CPU paired delta regressed to p50 `+466.35 us` (`+29.339%`)
and p95 `+907.4 us`; only 1/10 pairs favored the optimized run. This therefore
supports a narrow reduction in measured GPU workload time, not a claim of
better total frame time, CPU efficiency, FPS, or game-wide performance.

## Reproduction

```powershell
dotnet run --project src/FluidRuntime -c Release -- hook-lab `
  --target native/build/Release/fluidruntime-hook-target.exe `
  --hook native/build/Release/fluidruntime-present-hook.dll `
  --frames 120 --hold-ms 500 --gpu-timeout-ms 1000 `
  --hardware false `
  --out artifacts/subresource-provenance.json
```

This evidence proves conservative subresource state reconstruction in the owned
workload. It is not a claim that regional copies can yet be removed in games.
