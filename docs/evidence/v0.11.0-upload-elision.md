# FluidRuntime v0.11.0 Upload Elision Evidence

## Result

FluidRuntime can now classify and reversibly suppress repeated D3D11
whole-resource uploads inside its owned laboratory:

`STAGING + CPU_WRITE -> DEFAULT`

The source is written once through `Map`/`Unmap`. The first copy is required.
The next 64 copies use the same trusted source generation and unchanged
destination. Action 4 authorizes only that direction; generic action 1 and
readback action 2 cannot spend its budget.

Each optimized run:

- observes 65 upload copy calls;
- forwards 1 and skips exactly 64;
- avoids 268,435,456 logical copy bytes;
- retains one successful 4 MiB CPU write map/unmap;
- produces the same expected, staging-source, and default-destination FNV-1a
  hash;
- exhausts the exact 64-action policy budget;
- detaches and restores original dispatch before final readback.

## RX 580 Measurement

Adapter: AMD Radeon RX 580 2048SP, LUID `000000000000e914`.

| Metric | Baseline p50 | Optimized p50 | Baseline p95 | Optimized p95 |
| --- | ---: | ---: | ---: | ---: |
| CPU submission QPC | 11,989.250 us | 11,987.300 us | 13,397.080 us | 12,391.395 us |
| GPU timestamp interval | 31,883.320 us | 1,669.600 us | 32,520.304 us | 1,734.448 us |

Paired evidence:

- GPU optimized wins: 10/10.
- GPU paired delta p50: -30,432.080 us (-94.814%).
- GPU paired delta p95: -29,132.892 us (-94.445%).
- CPU optimized wins: 6/10.
- CPU paired delta p50: -109.750 us (-0.910%).
- CPU paired delta p95: +377.070 us (+3.198%).
- CPU pairs inside the predeclared +1,000 us / +10% envelope: 10/10.

`CopyResource` is asynchronous command submission. The positive gate therefore
requires strict GPU p50/p95 improvement and at least 80 percent GPU wins, while
every CPU submission pair must remain inside the declared overhead envelope.
It does not claim CPU acceleration. The guarded GPU value is a timestamp
interval around the owned workload, not a hardware GPU-busy counter.

## Claim Scope

The performance gate passed only for:

`owned-d3d11-writable-staging-to-default-upload-copy-workload-only`

Claim basis:

`gpu-interval-improvement-with-bounded-cpu-submission-overhead`

This proves API-visible D3D11 upload-copy elision in the deterministic owned
workload. It does not prove:

- physical RAM-to-VRAM or PCIe byte reduction;
- resource residency, migration, eviction, or placement;
- identical data across separate CPU writes;
- dynamic-buffer or `UpdateSubresource` optimization;
- external-game support, FPS, frame latency, power, or machine-wide gains.
