# FluidLink v0.14.0 Positional Binary Interoperability Evidence

Recorded on 2026-08-01 between FluidRuntime 0.14.0 and FluidGateway 0.64.0.

## Scope

This gate verifies the local advisory control transport between the two public
repositories. It proves cross-language agreement on framing, payload schemas,
fixed-point units, correlation, and one modeled duplicate-upload decision.

It does not prove physical RAM/VRAM placement, PCIe traffic, game FPS, power,
external-game safety, or authority to actuate the native hook.

## Contract

- protocol: `fluidlink-v2`;
- package: `FluidLink` 0.2.0;
- transport: TCP loopback;
- header: fixed 56-byte little-endian binary;
- payload: opcode-specific positional binary, no JSON;
- time unit: integer microseconds;
- memory unit: integer bytes;
- maximum payload: 65,535 bytes;
- capability registry: unsigned 64-bit mask;
- contract SHA-256:
  `0d24d96aec32d74e123f9e198e51adde74ddf190e8c40b0ac18bddf5c4108b2f`;
- golden-vector SHA-256:
  `3afb2a04373b1a21bd36fe9580c2adc95b38a619d1c4d8864205eaf45bcf6216`.

The integration script hashes the Gateway and Runtime copies of the v1
contract, v2 contract, and v2 golden vectors before opening a connection.
The shared v2 fixture has 17 complete frames covering every message/event
opcode, lifecycle endings, all optional masks, execute/deduplicate decisions,
one numeric `invalid_payload` error, and heartbeat. Other decision/error values
are codec-tested without one full-frame vector each.

## Method

The probe opens two sequential connections to the same Gateway process. One
uses FluidLink v1 and one uses FluidLink v2. Each connection performs the same
semantic flow:

1. Hello/Welcome and heartbeat;
2. begin one session and one frame;
3. register one 64 MiB RAM buffer and one 64 MiB VRAM-intent buffer;
4. submit one 800 us upload intent;
5. submit an identical second upload intent;
6. end frame/session and close cleanly.

Both first uploads were accepted as executed. Both duplicate uploads returned
decision opcode `2`, `deduplicate-identical-transfer`, with `executed=false`.
The v2 decision encoded exact estimates of `800` microseconds and `67,108,864`
bytes.

## Result

| Measurement | FluidLink v1 | FluidLink v2 |
| --- | ---: | ---: |
| Request frame bytes | 1,755 | 1,032 |
| Response frame bytes | 1,434 | 848 |
| Total frame bytes | 3,189 | 1,880 |
| Round trips | 11 | 11 |

FluidLink v2 used 1,309 fewer frame bytes, a 41.05% reduction for this exact
control flow. Counters cover complete FluidLink frames handed to TCP and exclude
TCP/IP overhead.

The functional v2 session also recorded application RTT p50 `3,166 us` and p95
`28,809 us`. Eleven samples include handshake and Python scheduling, so this is
visibility data, not a sustained transport benchmark and not sufficient by
itself to justify or reject shared memory.

## Feedback Decisions

- JSON payload removal: implemented in v2.
- Numeric opcodes: retained and extended with capability and presence masks.
- Fixed-point values: implemented at the wire boundary.
- Delta snapshots: deferred because the current state event carries only a
  one-byte request and no repeated snapshot body to compress.
- Shared-memory FluidLink: deferred pending a separate synchronization,
  backpressure, identity/ACL, crash-recovery, and benchmark contract. The
  existing hook ring remains a separate native ABI.

## Review Hardening

- Python preserves all accepted `*_us` aliases as microseconds instead of
  accidentally scaling nested `target_frame_us` by 1,000.
- Python rejects implicit identifier/list-item coercion and registration-only
  fields on resource-release messages.
- Malformed binary event payloads return numeric `invalid_payload`; adapter
  rejection remains the separate `runtime_event_rejected` condition.
- The .NET client preserves a negotiated session only for a recoverable runtime
  rejection. Sequence, session, correlation, framing, and other peer failures
  invalidate local state and require a new handshake.
- Complete release suites pass: FluidGateway 242/242 and FluidRuntime 113/113.
