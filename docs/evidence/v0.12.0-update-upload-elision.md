# FluidRuntime v0.12.0 UpdateSubresource Elision Evidence

## Result

FluidRuntime can now suppress repeated, byte-identical D3D11
`UpdateSubresource` uploads inside its owned cooperative laboratory.

The bounded scope is one full 4 MiB `D3D11_USAGE_DEFAULT` buffer, subresource
zero, no destination box, zero row/depth pitch, one exact-content cache entry,
and action 8. The hook does not authorize this path from generic copy action 1,
readback action 2, or staging upload action 4.

Each run issues 67 direct uploads:

- one required upload of content A;
- 32 repeated A uploads;
- one required upload of content B, differing by one bit;
- 16 repeated B uploads;
- one external `CopyResource` write of distinct content C;
- one required re-upload of B after that generation change;
- 16 more repeated B uploads.

Baseline runs forward all 67 direct uploads. Optimized runs forward the three
required uploads and skip exactly 64 byte-identical repeats. Including three
legacy observation updates, native totals are 70 forwarded updates in baseline
and 6 in optimized runs.

## Safety Proof

- Exact `memcmp`, not pointer identity or hash equality, decides redundancy.
- FNV-1a hashes are evidence labels; they are not the skip proof.
- The A-to-B mutation must be forwarded because bytes differ.
- The C write must invalidate B even though the later source bytes still equal
  the cached B image; the next B update is forwarded because the destination
  generation changed.
- The exact-content cache is opt-in and bounded to one resource / 4 MiB.
- Resource retirement removes its cache entry; detach drains active calls,
  restores dispatch, clears the cache, and leaves stale entrypoints
  observation-neutral.
- Every optimized run exhausts exactly 64 action-8 reservations.
- The final destination hash equals B and differs from both A and C.

## Claim Scope

The performance gate passed only for:

`owned-d3d11-default-buffer-full-update-subresource-exact-content-workload-only`

Claim basis:

`gpu-interval-improvement-with-bounded-cpu-content-comparison-overhead`

Microsoft documents that `UpdateSubresource` snapshots application memory
before returning and may use a CPU temporary copy plus an asynchronous GPU copy
when the destination is contended. The exact physical path remains architecture
and driver dependent. See
[ID3D11DeviceContext::UpdateSubresource](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-updatesubresource).

This release does not prove:

- physical RAM-to-VRAM or PCIe byte reduction;
- texture, partial-box, constant-buffer, dynamic-buffer, deferred-context, or
  `UpdateSubresource1` support;
- correctness across unobserved shader writes, command lists, aliases, fences,
  queries, or concurrent immediate-context calls;
- external-game support, FPS, frame latency, power, or machine-wide gains.
