# FluidLink Resilience and Update-Upload 128 Evidence v0.18.0

Recorded on 2026-08-11 between FluidRuntime 0.18.0, FluidLink 0.3.0,
and FluidGateway 0.66.0.

## Scope

This release hardens the local decision server and uses the existing native
action ceiling more fully. It does not change either FluidLink v2 fingerprint,
the native hook ABI, the one-resource cache, or the 128-action policy maximum.

The owned UpdateSubresource profile now defaults to:

- one 4 MiB D3D11 default buffer;
- one seed plus 128 exact duplicate candidates in a 129-operation batch;
- three required direct updates and 128 redundant direct updates;
- one 4 MiB retained-content cache and exact `memcmp` as the final gate;
- one short-lived action-8 policy with budget 128.

The historical 64-candidate profile remains selectable and passed its WARP
regression gate.

## Server Resilience

FluidGateway now serves local connections through a bounded eight-worker
server with a backlog of 16. Legacy JSONL, FluidLink v1, and FluidLink v2 share
the same limit. Excess clients are closed without processing input.

Read waits are monotonic absolute deadlines:

| Phase | Default |
| --- | ---: |
| Initial magic and version | 1,000 ms |
| In-progress frame | 2,000 ms |
| Idle completed session | 30,000 ms |

The deadline does not restart when a peer drips another byte. The regression
suite covers cross-connection stalled headers, initial and in-frame slow drip,
saturation and slot recovery, idle expiry, loopback-only binding, synchronous
`--once`, and active-worker shutdown. All eight cases passed ten consecutive
runs. The complete Gateway suite passed 257/257.

## RX 580 Native Timing

Adapter: AMD Radeon RX 580 2048SP, vendor `0x1002`, device `0x6fdf`, LUID
`000000000000ea24`. Host WMI reported driver `31.0.21924.61`, dated
`2025-12-11T00:00:00Z`; driver metadata is not embedded in the native trace.
Twenty measured pairs alternated baseline/optimized order; one warmup pair was
excluded.

| Metric | Baseline p50 | Optimized p50 | Delta p50 | Baseline p95 | Optimized p95 | Delta p95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| CPU workload | 513,913.200 us | 109,128.350 us | -78.780% | 528,330.055 us | 114,460.205 us | -75.039% |
| GPU timestamp interval | 469,330.660 us | 3,427.360 us | -99.276% | 484,285.696 us | 3,760.008 us | -99.148% |

CPU stayed inside the declared comparison-overhead gate in 20/20 pairs. GPU
timing was valid and favored optimized in 20/20 pairs. The native owned-workload
gate therefore passed.

Gateway authorization p50/p95 was 24,512 / 35,490 us across 21 runs. It remains
outside the native timing interval, so the Gateway-managed report correctly
sets `performance_claim_allowed=false` with blocker
`gateway-authorization-outside-native-timing-window`.

## Evidence Boundary

This release supports a positive claim only for the timed native interval of
the owned full-buffer D3D11 workload. It does not claim faster games, FPS,
frame latency, lower power, physical RAM/VRAM placement, PCIe reduction,
textures, partial uploads, external-process support, D3D12 actuation, Vulkan,
or a general scheduler.
