# v0.22 Native Vulkan Evidence

Verified locally on 2026-09-05. This milestone implements a native cooperative
Vulkan buffer-transfer DLL, not a loader interception layer or external-game
hook. See [the library contract and reproduction steps](../vulkan-native.md).

## Result

The owned workload passed exact readback, ordered IPC, bounded authorization,
invalidation and all-forwarded rollback checks. Thirty measured AB/BA pairs
showed lower native GPU intervals and lower complete managed time in every
controlled run. These are descriptive results for deliberately redundant
private buffers, not evidence of game FPS, input latency or energy savings.
The report retains `native_execution_gate_passed=true` and
`performance_claim_allowed=false`.

## Method

- Windows x64, AMD Radeon RX 580 2048SP, Vulkan API 1.3.260.
- MSVC 19.51, Windows SDK 10.0.26100; Release build without ASAN or validation
  for timing. Compilation had finished before the measured run.
- One warmup pair excluded, then 30 measured pairs alternating AB/BA within
  the measured phase. One private graphics-capable queue, two primary command
  buffers, two isolated 4 MiB destinations and one fence.
- Each measured phase tracks 136 full-buffer copies. Baseline forwards all;
  controlled forwards eight and omits 128 exact duplicates. Four additional
  rollback copies are always forwarded. All runs check source mutation, fill,
  explicit invalidation, recording reset, exact output and zero IPC loss.
- Each controlled run omits 536,870,912 logical API bytes (512 MiB). This is
  not measured physical bus traffic or reduced VRAM allocation.
- GPU intervals sum the two lane durations. Native workload includes CPU
  recording, submission and verification. Managed end-to-end also includes
  authorization, child startup, the fixed 150 ms hold, readback and rollback.

```powershell
./tools/Test-GatewayManagedVulkanCopy.ps1 `
  -BuildPath native/build-vulkan -TrialPairs 30 -WarmupPairs 1 `
  -CandidateActionCount 128 -OutputPrefix vulkan-rx580-v022
```

## Correctness And Regression Gates

- Gateway Python: 270/270 tests.
- Runtime .NET: 229/229 tests with warnings treated as errors, including 28
  Vulkan cases for options, authorization domain/topology and evidence tampering.
- Native CTest: 31/31 in Release, Debug and AddressSanitizer configurations.
  ASAN ran with `halt_on_error=1:abort_on_error=1:detect_leaks=0`; this does not
  establish leak-freedom or driver safety.
- MSVC code analysis: Vulkan DLL and target clean with analyzer and compiler
  warnings treated as errors.
- Khronos ValidationLayers 1.3.290, source commit
  `a92629196a4fed15e59c74aa965dd47bd5ece3b7`: core and synchronization validation
  passed baseline, controlled and guard runs at 128 candidates. Final Gateway
  integration also passed two measured pairs and three authorization faults
  with the same target/library hashes as the timing run.
- Validation runs reported zero API/synchronization warnings and errors,
  including teardown. Eight general loader notices per run record intentionally
  disabled implicit overlays; they remain visible in native diagnostics.
  Validation timings are separate and not part of the benchmark above.
- Malformed, stalled and cumulatively slow authorization peers each produced a
  fresh verified baseline without publishing an action policy.
- Existing D3D11/D3D12 Gateway authorization regressions passed on WARP,
  including all three failure paths. FluidLink cross-process checks passed
  11 v1 and 11 v2 round trips; no wire schema or Gateway release pin changed.

Hosted CI builds Vulkan and tests policy/parsing without requiring a Vulkan
driver. The hardware checks above are local results, not claims about hosted
GPU coverage. Publication/CI state is visible in GitHub Actions.

## Limits And Next Step

This single-adapter synthetic workload does not establish benefits in an
engine or game. It excludes images, partial copies, aliased/sparse/external
memory, secondary command buffers, multiple queues and external GPU writers.
CPU shadows and staging allocations are explicit overhead, not memory savings.

The RX 580 selected host-coherent upload/readback memory (flags 6) and
device-local destination memory (flags 1). Non-coherent flush/invalidate code
exists but was not exercised on non-coherent hardware. A CPU Vulkan ICD,
device-loss recovery and deliberately hung drivers were not tested. No driver
reset, registry change, global layer installation or external-process action
was performed.

Next: add opt-in Vulkan observation on a representative application/engine,
including memory bindings and write provenance, before broadening authority
to borrowed resources or an interception layer. First measure the frequency
of real redundancy and the cost of detecting it; this lab alone cannot answer
whether that tradeoff wins in games.
