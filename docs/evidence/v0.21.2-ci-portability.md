# FluidRuntime v0.21.2 CI Portability

Recorded on 2026-08-14. This is a release-infrastructure hotfix over v0.21.1;
it does not change native authority, transfer semantics, or wire contracts.

## Root Cause

The initial v0.21.1 workflow searched for
`clang_rt.asan_dynamic-x86_64.dll` only below `Program Files (x86)`. The current
GitHub Windows runner selected Visual Studio 18 from `Program Files`, so the
ASAN build succeeded but the test step could not add its runtime directory to
`PATH`.

## Fix

The workflow now reads `CMAKE_AR:FILEPATH` from the ASAN build's
`CMakeCache.txt`, derives the exact selected MSVC tool directory, verifies the
runtime DLL beside those tools, and scopes that directory to the ASAN test
step's `PATH`.

Normal Release and Debug binaries remain non-ASAN builds and do not depend on
the ASAN runtime. The v0.21.1 local-use hardening evidence remains applicable.

## Release Gate

- Managed tests: 194/194 locally.
- Native CTests: 21/21 Release and 21/21 Debug locally.
- ASAN CTests: 21/21 locally with the runtime directory derived from the CMake
  cache.
- Remote CI and FluidLink interoperability are required on the release commit
  and tag before this hotfix is considered complete.
