# FluidLink v0.13.0 Binary Interoperability Evidence

## Scope

This gate verifies the local control transport between FluidRuntime 0.13.0 and
FluidGateway 0.63.0. The tested scope is:

`loopback-binary-control-framing-with-json-dynamic-payload`

FluidLink carries advisory runtime intent and compact Gateway decisions. This
release does not change the native hook, shared-memory ABI, actuation policy, or
the v0.12.0 hardware claim.

## Contract

- protocol: `fluidlink-v1`;
- package: `FluidLink` 0.1.0;
- fixed header: 56 bytes, little-endian;
- payload: strict UTF-8 JSON object, maximum 1 MiB and depth 64;
- contract SHA-256:
  `10b46685472d13d2d49cc81aa1f7df2d654c1ec53fdc666e086e0d062ad114fa`.

The integration gate compares the two committed manifest files. Hello and
Welcome then negotiate that same fingerprint inside the live connection.

correlated response for each request.

The SDK generates the JSON comparison from the same frame semantics, payloads,
message IDs, session IDs, numeric opcodes, and line termination. Frame counters
cover application bytes delivered to TCP; they exclude TCP/IP overhead.

## Decision Result

The first synthetic 64 MiB RAM-to-VRAM upload intent returned `executed=true`.
The identical second intent returned decision opcode `2`
(`deduplicate-identical-transfer`) and `executed=false`, with modeled estimates
of 0.8 ms and 64 MiB saved.

Those estimates come from the Gateway model. The probe does not execute or skip
a D3D11 call and does not measure physical RAM, VRAM, PCIe, latency, FPS, power,
or game behavior.

## Authority Boundary

FluidLink is loopback user-space IPC without hostile-peer authentication. A
decision cannot authorize the native hook. Native actuation still requires an
independent owned-target gate covering provenance, exact action, budget,
expiration, equivalence, evidence, and rollback.
