# v0.7 Resource Lifecycle Evidence

Captured on 2026-07-12 with the final v0.7.0 implementation. This slice validates
cooperative resource retirement in the owned D3D11 target. It does not claim
automatic observation of COM destruction or support for external processes.

## Contract

- Shared-memory ring ABI: 2
- Resource IDs are non-zero, unique, and monotonic.
- Retirement removes the resource from active state and invalidates dependent
  copy provenance.
- Recent pointer reuse links one retired ID to one fresh active ID.
- Writes and copies may only reference active IDs.
- Reuse without a prior retirement is a provenance failure.
- Retired-pointer history is bounded to 4,096 identities.

## Reproduction

```powershell
dotnet run --project src/FluidRuntime -c Release -- hook-lab `
  --target native/build/Release/fluidruntime-hook-target.exe `
  --hook native/build/Release/fluidruntime-present-hook.dll `
  --frames 120 `
  --hold-ms 500 `
  --gpu-timeout-ms 1000 `
  --hardware false `
  --out artifacts/resource-lifecycle.json
```

Pointer reuse is allocator and driver dependent. A run may report zero reuse and
remain valid; safety comes from assigning fresh IDs on every observed creation,
not from requiring reuse to occur.
