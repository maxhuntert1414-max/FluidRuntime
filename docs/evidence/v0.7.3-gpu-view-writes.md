# v0.7.3 GPU-View Write Evidence

Captured on 2026-07-15 with the final v0.7.3 implementation. This slice closes
two known holes in the owned D3D11 provenance model: render-target clears and
floating-point UAV clears. It does not establish complete shader-write tracking
or safety for an external process.

## Contract

- Snapshot ABI v8 and 80-byte ring ABI v5 add
  `ClearRenderTargetView` and `ClearUnorderedAccessViewFloat` events.
- The hook resolves an owned view to its resource and exact Texture2D mip before
  forwarding the original API call.
- Exact writes carry flag `8`, the addressed subresource, its new generation,
  and an estimated logical byte count.
- A write to mip 0 preserves mip-1 copy provenance. A write to mip 1 invalidates
  the next mip-1 repeat.
- Unsupported or multi-subresource tracked views conservatively invalidate the
  whole resource.
- Views for resources created before attach are excluded from owned provenance;
  frame-loop backbuffer clears therefore do not fabricate resource state.
- All clear calls and all `CopySubresourceRegion` calls are forwarded.
- Native snapshot counts, managed IPC events, exact event order, lifecycle
  state, content hashes, and rollback must agree without loss.

The hooked operations follow the documented D3D11 view boundaries:
[ClearRenderTargetView](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-clearrendertargetview) and
[ClearUnorderedAccessViewFloat](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-clearunorderedaccessviewfloat).

- Regional candidates: 5 calls / 5,120 bytes
- `ClearRenderTargetView`: 1 exact mip-0 write / 4,096 bytes
- `ClearUnorderedAccessViewFloat`: 1 exact mip-1 write / 1,024 bytes
- Provenance and Release-hook failures: 0
- Source/destination mip hash: `a248d64aeaf94d25`

The sequence first proves that both an `UpdateSubresource` and an RTV clear on
mip 0 preserve a repeated mip-1 candidate. It then updates mip 1, distinguishes
two partial destination regions, and recognizes a later exact full-region
repeat. Finally, the UAV clear on mip 1 makes the next full copy non-redundant;
only the following unchanged repeat becomes a candidate.

## AMD Hardware Run

- Adapter: AMD Radeon RX 580 2048SP
- Trial design: 1 excluded warmup pair and 10 measured pairs
- Native/managed runs: 22
- GPU timing valid: 10/10 measured pairs
- ABI-v5 GPU-view/subresource contract valid: 22/22 runs
- Automatic destructions: 1,408 total
- Provenance and Release-hook failures: 0
- Content and rollback valid: 22/22 runs

The positive-performance gate was **blocked**. GPU paired delta was p50
`-2.08 us` (`-4.002%`) but p95 `+0.576 us`; 9/10 pairs favored the optimized
run and 1/10 favored the baseline. CPU paired delta was p50 `+192.25 us`
(`+10.091%`) and p95 `+626.79 us`. The trace therefore supports the correctness and
observability contract, but no positive performance claim for v0.7.3.

## Reproduction

```powershell
dotnet run --project src/FluidRuntime -c Release -- hook-lab `
  --target native/build/Release/fluidruntime-hook-target.exe `
  --hook native/build/Release/fluidruntime-present-hook.dll `
  --frames 120 --hold-ms 500 --gpu-timeout-ms 1000 `
  --hardware false `
  --out artifacts/gpu-view-writes.json
```

This evidence proves exact attribution for two clear operations in the owned
immediate-context workload. It does not prove complete GPU-write tracking,
external injection safety, regional copy elision, or game-wide performance.
