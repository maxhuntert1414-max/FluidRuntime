# v0.9.0 Sustained Managed Copy-Elision Evidence

Captured on 2026-07-26 from the final v0.9.0 release. This release extends
the owned D3D11 managed control plane from one action to a bounded batch and
demonstrates measurable removed GPU copy work on the local RX 580.

The claim is deliberately narrow:

`owned-d3d11-sustained-copy-elision-gpu-workload-only`

It is not a game-wide FPS, frame-time, power, RAM/VRAM, or CPU-scheduling claim.

## Contract

- Snapshot ABI v9, attach-options ABI v2, ring ABI v6, and control ABI v1 keep
  their existing layouts.
- The existing `action_budget` field now accepts values from 1 through 128.
- Epoch, action mask, maximum four-second lifetime, target opt-in, atomic
  reservation, acknowledgment, expiration, and fail-closed status rules remain.
- The legacy `manager-lab` still publishes budget one and behaves unchanged.
- `wrong-budget` now publishes 129 and must be rejected.
- The sustained target creates a 4 MiB source/destination buffer pair, forwards
  one required initial copy, and issues 128 unchanged repeats before the legacy
  six-copy workload.
- A valid optimized run must apply exactly 128 actions, finish `exhausted`,
  forward 7 total `CopyResource` calls, skip 128, and avoid 536,870,912 logical
  bytes.
- Baseline must observe and forward all 135 calls and 541,114,368 bytes.
- Every run requires exact sustained/small-buffer/texture/subresource readback,
  stable hashes, event/snapshot agreement, zero loss/overrun, and restored
  dispatch after detach.

Microsoft documents `CopyResource` as an asynchronous GPU whole-resource copy.
The lab therefore uses the existing D3D11 timestamp queries inside a
`TIMESTAMP_DISJOINT` interval and rejects invalid/disjoint/zero-frequency data.

## AMD RX 580 Hardware Run

- Adapter: AMD Radeon RX 580 2048SP (`1002:6FDF`)
- Design: 1 excluded warmup pair + 10 measured pairs
- Native/managed processes: 22
- IPC events: 7,923 with zero sequence loss or native overrun
- GPU timing valid: 10/10 measured pairs
- GPU optimized wins: 10/10

- GPU paired p50 delta: `-21,174.56 us`
- GPU paired p95 delta: `-18,560.784 us`
- GPU paired percent delta p50: `-98.543%`
- GPU paired percent delta p95: `-98.151%`
- CPU p50: baseline `8,322.45 us`, optimized `8,477.45 us`
- CPU paired p50 delta: `+252.95 us`
- CPU paired p95 delta: `+885.81 us`

The scoped GPU-workload performance gate passed: all measured GPU pairs favored
the optimized run and both GPU p50 and p95 improved. CPU timing regressed, so
v0.9.0 does not claim end-to-end frame, CPU, or game performance improvement.
The result proves that the manager can remove a bounded batch of real queued GPU
copy work under the owned workload while preserving content and rollback.

```powershell
  --release-target native/build/Release/fluidruntime-hook-target.exe `
  --release-hook native/build/Release/fluidruntime-present-hook.dll `
  --debug-target native/build/Debug/fluidruntime-hook-target.exe `
  --debug-hook native/build/Debug/fluidruntime-present-hook.dll `

  --target native/build/Release/fluidruntime-hook-target.exe `

  --hold-ms 50 --gpu-timeout-ms 5000 --hardware true `
  --out artifacts/sustained-copy-hardware.json
```

## Limits

- Owned cooperative D3D11 target only.
- The repeated-copy identity is deliberately constructed and proven by the
  existing provenance model.
- No external attach, remote injection, anti-cheat interaction, or driver hook.
- No claim that 512 MiB of logical removed copies equals physical PCIe/VRAM
  traffic one-for-one.
- No CPU, RAM/VRAM residency, presentation, FPS, or old-machine claim.
- The next step is to derive similarly bounded policies from live evidence and
  expand synchronization/provenance coverage before external actuation.
