# v0.23 Application Integration Evidence

Verified locally on 2026-09-05, Windows x64, AMD Radeon RX 580 2048SP,
MSVC 19.51, .NET 10 and Python 3.14. This milestone is **external Vulkan
observation plus an opt-in Windows priority lease**, not external GPU elision.
See [the application-session contract](../application-sessions.md).

## Compatibility And Lifecycle

The unmodified cube application sources from Khronos Vulkan-Tools v1.3.290,
commit `b47676a03827fc0c287409b243b1fd62886e79c0`, were built locally as x64
`vkcube.exe` and `vkcubepp.exe`. No FluidRuntime SDK calls or source edits were
added to those applications. This establishes third-party integration with
two diagnostic programs, not general compatibility with commercial games.

- Eight AB/BA pairs of `vkcube --c 120 --use_staging --suppress_popups` passed.
  Each pair used identical executable, layer and argument hashes; priority
  remained unchanged. All processes exited naturally with code zero.
- Every observed run recorded 120 present calls, 121 submits, six allocations
  and six frees, one buffer/image copy and zero live tracked bytes at exit.
  Active instance/device counts, API errors and untracked allocations ended at zero.
- Requested allocations totaled 1,068,624 bytes: 265,792 host-visible and
  802,832 device-local in this sample. These are logical requests, not measured
  physical residency, transfer traffic, or saved memory.
- A separate one-second Normal -> AboveNormal lease was applied and restored
  to Normal in 1,004.111 ms. No scheduling benefit is inferred from that success.
- In the deliberate collector-termination test, the independent two-second
  watchdog restored Normal after 2,003.811 ms. The 600-frame diagnostic target
  then exited naturally. This does not cover killing the watchdog itself.
- A one-second capture stopped while a 300-frame target was still alive (58
  present calls captured). Priority was restored and the target subsequently
  exited naturally. Capture expiration does not terminate the application.

## Timing Boundary

Compilation and other project tests were stopped before the eight measured
pairs. No warmup was excluded. Default local overlay environment was retained;
validation/ASAN were disabled for these runs. Values are collector wall-clock
milliseconds, including startup, polling and teardown observation.

| Metric | p50 | Minimum | Maximum |
| --- | ---: | ---: | ---: |
| Baseline capture duration | 2591.708 | 2586.258 | 2595.151 |
| Observed capture duration | 2362.920 | 2360.147 | 2367.238 |
| Paired observed minus baseline | -226.937 | -232.070 | -226.091 |

**These differences do not prove acceleration or negligible overhead.** They
are close to the 250 ms sampling period and mix loader/startup/presentation
effects with exit-detection quantization. The layer removes no GPU operations.
No per-frame PresentMon timing, energy measurement, image equivalence comparison,
or fine-resolution engine overhead study was performed in this milestone.
Every application report retains `performance_claim_allowed=false`.

## Correctness Gates

- Gateway: 278/278 tests, including eight application-report tests. Output
  collisions cannot overwrite raw evidence; contradictory priority restoration
  and actuation/performance promotion are rejected.
- Runtime: 245/245 .NET tests, warnings-as-errors, including 16 session cases
  covering opt-in parsing, opaque application arguments, scope/priority bounds,
  manifest binding, mapped ABI tampering and revocation.
- Native: 32/32 CTest cases in Release, Debug and ASAN. New mock-driver coverage
  exercises 100 instance/device lifecycles, unknown/unsupported extension
  dispatch, unchanged negative results, counter agreement, driver-handle reuse
  and cached downstream destruction. It runs without a Vulkan GPU in hosted CI.
- MSVC analysis: observation DLL and mock tests passed with compiler and analyzer
  warnings treated as errors. ASAN used `halt_on_error=1:abort_on_error=1:detect_leaks=0`;
  that is not leak-freedom or driver memory-safety proof.
- Direct `vkcubepp` with our mapped layer and Khronos ValidationLayers 1.3.290
  (`a92629196a4fed15e59c74aa965dd47bd5ece3b7`) passed 120 presents and natural
  teardown in Release, Debug and ASAN. Core and synchronization validation
  reported no validation warnings/errors. Loader notices about intentionally
  disabled implicit overlays are retained in the raw diagnostics.
- These direct validation runs explicitly used `VK_LAYER_PATH`,
  `VK_INSTANCE_LAYERS=VK_LAYER_FLUIDRUNTIME_observe;VK_LAYER_KHRONOS_validation`,
  `VK_LAYER_ENABLES=VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT`,
  `VK_LOADER_LAYERS_DISABLE=~implicit~` and `VK_LOADER_DEBUG=layer`, only in the
  child environment. Logs confirm both layers loaded and unloaded at process
  exit. They are distinct from Runtime's normal application A/B sessions.
- Existing owned Vulkan Gateway authorization passed two correctness pairs and
  malformed/stalled/slow peer rejection. This short regression is not a new
  performance benchmark. FluidLink cross-process v1/v2 round trips passed;
  no wire contract or Gateway release pin changed.

## Bugs Found During Development

Late downstream lookup of destruction functions could reenter the loader's
top dispatch table and recurse during teardown. Functions are now cached during
creation, before top-table installation; a mock simulates the hazardous lookup.
Allocation bookkeeping now retires a handle before forwarding its free, avoiding
misattribution if the driver reuses that handle concurrently. A reentrant reuse
regression distinguishes old 128-byte and replacement 256-byte allocations.
